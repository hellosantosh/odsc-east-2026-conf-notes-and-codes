AI teams run evaluations but often lack the tools to answer the follow-up questions: Did the model actually get better? Which samples regressed? Is the improvement statistically significant or just noise? This session walks through building a production evaluation pipeline with MLflow, covering three layers that work together. First, we connect external evaluation libraries to MLflow using the third-party scorer interface. You will see how Phoenix (hallucination detection), TruLens (groundedness and agent trace evaluation), and Guardrails AI (deterministic safety validators like toxicity and PII detection) plug into mlflow.genai.evaluate() so teams can run safety and quality checks from a single entry point without switching tools. Second, we look at practical infrastructure decisions: controlling LLM judge parameters (temperature, top_p) for reproducible scoring, managing scorer concurrency to avoid rate limits, and using uv lockfiles to pin model dependencies so environments match between training and serving. Third, we build a comparison workflow that aligns samples across two evaluation runs by ID, computes per-sample score deltas, and runs statistical significance tests (bootstrap confidence intervals for continuous scores, McNemar's test for binary pass/fail outcomes) to determine whether a model change is a real improvement or within the margin of error. Attendees will leave with working code for each layer and a clear picture of how to set up evaluation pipelines that go beyond "run eval, check accuracy" to "run eval, compare, and prove the difference matters." This session is aimed at ML engineers, data scientists, and platform teams building or maintaining LLM-powered applications in production.
